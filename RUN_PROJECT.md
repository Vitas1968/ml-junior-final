# Инструкция по запуску проекта после клонирования репозитория

В репозитории **не хранятся исходные данные, производные датасеты и артефакты моделей**
из-за ограничений по объёму и требований курса.

Ниже приведена пошаговая инструкция,
как развернуть и запустить проект локально после клонирования.

## 0. Краткая пошаговая инструкция как развернуть и запустить проект локально после клонирования.

1. Клонировать репозиторий:

bash
git clone <repo_url>
cd ML_Junior_final
2. Создать и активировать виртуальное окружение (Windows):

bash
python -m venv .venv
.venv\Scripts\activate

3. Установить зависимости

bash
pip install -r requirements.txt

4. Подготовить данные вручную:

В репозитории отсутствуют данные. Необходимо вручную восстановить следующую структуру:
data/
├── raw/
│   ├── train_data_0.pq
│   ├── train_data_1.pq
│   ├── ...
│   └── train_data_11.pq
├── target/
│   └── train_target.csv
└── processed/

5. Запустить обучение (включает preprocessing):

bash
python -m src.pipeline

Результат:

artifacts/model.pkl — финальная модель (обучена на всём датасете)
artifacts/predictions.csv — предикты на test-выборке

6. Запустить инференс (CLI):

bash
python -m src.predict

Через некоторое время аосле запуска скрипт покажет случайные id и предложит ввести id вручную

# Развернутая инструкция по запуску проекта после клонирования репозитория

## 1. Клонирование репозитория

bash
git clone <repo_url>
cd ML_Junior_final

## 2. Создание и активация виртуального окружения

bash
Создание виртуального окружения:
python -m venv .venv

Активация окружения:
.venv\Scripts\activate

## 3. Установка зависимостей
pip install -r requirements.txt

## 4. Подготовка данных
В репозитории отсутствуют данные.
Необходимо вручную восстановить следующую структуру:
data/
├── raw/
│   ├── train_data_0.pq
│   ├── train_data_1.pq
│   ├── ...
│   └── train_data_11.pq
├── target/
│   └── train_target.csv
└── processed/

Назначение файлов:

train_data_*.pq — исходные parquet-файлы с кредитной историей;

train_target.csv — файл с целевой переменной (id, flag).

## 5. Preprocessing и формирование датасетов

⚠️ Ноутбуки не используются в production-flow.
Вся подготовка данных выполняется кодом из src/.

Preprocessing автоматически:

читает parquet-файлы итеративно;

агрегирует данные по id;

применяет Feature Engineering;

объединяет данные с целевой переменной;

сохраняет обработанные датасеты.

Preprocessing запускается автоматически при обучении модели,
отдельно запускать его не требуется.

Результат:

data/processed/dataset_with_target.pkl — датасет для обучения;

data/processed/dataset_features.pkl — датасет для инференса.

## 6. Обучение финальной модели

python -m src.pipeline

Pipeline выполняет:

1. preprocessing данных;

2. stratified train/test split (80/20);

3. обучение модели на train;

4. оценку качества по ROC-AUC на test;

5. сохранение test-предиктов;

6. финальное обучение модели на всём датасете;

7. сохранение финальной модели.

В результате будут созданы артефакты:

artifacts/
├── model.pkl # финальная модель (обучена на всём датасете)
└── predictions.csv # предикты на test-выборке 

## 7. Инференс по конкретному пользователю

Запуск инференса:
python -m src.predict

Скрипт:

загружает финальную модель;

загружает датасет признаков;

выводит 10 случайных id из датасета;

предлагает ввести id вручную;

возвращает вероятность дефолта в процентах
и текстовую интерпретацию риска.

Пример вывода:

Вероятность дефолта пользователя с id=1221701 примерно 41.47 % и имеет умеренный риск.

## 8. Примечание о ноутбуках

Каталог notebooks/ используется только для исследований:

EDA;

экспериментов с признаками;

подбора моделей и гиперпараметров.

Ноутбуки не требуются для запуска проекта
и не участвуют в финальном pipeline.
